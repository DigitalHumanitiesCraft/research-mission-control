About the method

Research Mission Control organizes knowledge work through AI Operators, bounded assignments, maintained project knowledge and proportionate checks. Its contracts make responsibility, permitted changes and the grounds of a result inspectable across working contexts.

Authorship and reuse

What the model explains

An AI Operator is an LLM-based agent configured within an AI harness with responsibilities, working instructions, knowledge and tools. Its role defines responsibility; its session supplies the current context. A new session reconstructs work from the recorded knowledge and evidence available to it.

Operator Knowledge describes working instructions. Project Knowledge records sources, interpretations, requirements and decisions. The harness supplies technical capabilities and permission controls. None of these alone grants authority to change a project.

The architecture defines these distinctions. The handover contract specifies assignments, results, findings and acceptance. The method in practice follows a complete example.

A worked example, with explicit limits

The Traceable project handovers source pack connects an authored requirements study to a prepared workshop. All records and materials are fictional. The interactive sequence illustrates how a replacement source could be interpreted, implemented and checked. It is not connected to running operators.

The split into Workshop Operations and Materials Operations is a teaching adaptation of the Operations role. The missed worksheet instruction, review, correction, acceptance, write-back and new-session resumption are additional fictional teaching events. The process walkthrough pauses for the visitor to apply the source change within the illustration, route the correction and explicitly simulate material acceptance. The first control advances the teaching scenario. It does not imply that Research needs approval to interpret an already governing source. Rewinding invalidates later simulated decisions. No actual acceptance is recorded in the source pack. The sponsor’s workshop-format choice H-01 remains unanswered throughout.

Separate Verification returns its complete initial finding first to the project owner. The owner determines acceptance and further routing. A successful technical check does not establish scholarly validity, learning or suitability for a particular use.

Adapt the method

Start with a bounded assignment and a maintained knowledge folder. Add operators when parallel work, specialized investigation or a separate assessment context has a concrete purpose. Define one responsible writer per artifact and keep reserved decisions explicit.

Promptotyping supplies the default approach to project knowledge. An external vault is optional and needs an explicit source-selection and write-back agreement. A fork is useful when adapting the method repository itself; it is not a prerequisite for initializing a project.

The start instructions guide a setup conversation in your language. The complete system prompt and initialization skill define the procedure. Available tools, filesystem access and session communication must be checked in your actual harness.

Evidence and further reading

The method is an inspectable proposal with executable artifacts. The recorded Context Stream pilot and recorded working-session analysis describe bounded observations. They do not demonstrate universal reliability or improved research outcomes.

Explore the method specification, role contracts, knowledge index and existing project views. Report reproducible issues through the repository issue tracker, using material suitable for publication.

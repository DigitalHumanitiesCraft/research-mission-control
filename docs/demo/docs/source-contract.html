Source and work adapters¶

The UI/model, source adapter and authored demo data are separate. The historical names SECOND_BRAIN_VAULT and second-brain-coverage-1 are technical compatibility names; they impose no personal directory structure.

Existing source reader contract¶

GET /api/research returns schema second-brain-coverage-1 with vault.documents, vault.links, repositories.documents and optionally repositories.links/mappings. Each document contains id, path, title, revision (SHA256 as 64 lowercase hex), tags and aliases arrays. path is a confined logical relative path, not the machine's absolute source root. For vault.documents, id equals path exactly. Repository documents use the existing repo: identity namespace. A link contains from, to, quote (nonempty original wording) and positive integer line. Both endpoints must exist; repository links remain within their repository.

GET /api/source?path=<logical path> returns {path,text,revision}; path must equal the requested logical identity. No inferred source or approximate identity is accepted. The original source bytes and revision remain separately inspectable. The reader validates these fields and labels a changed source revision.

The static adapter maps GET /api/research to demo-assets/coverage.json. It reads source-map.json, whose exact keys are logical source identities and values are relative JSON response files inside this package. For example {"demo-guide":"demo-assets/source.json"}. GET /api/source looks up only an own entry in that map, then reads that file. Unknown keys, foreign origins, escaping/hidden paths and writes are rejected before native fetch. This consumes the same selected-file catalog produced by a project adapter; no new UI API is introduced.

A file-selection generator can read arbitrary explicitly selected project Markdown files. Its private configuration names source roots and selection, metadata and literal links. Keep the absolute roots/configuration outside the published package. Produce the existing coverage data, source-map and matching JSON source responses in a separate output directory; review them before choosing to publish. Never overwrite the synthetic demo automatically with user files. The method package's source-selection tool owns that configuration; this UI consumes its existing output shapes.

SECOND_BRAIN_VAULT exposes href(reference,anchor), isOpen(url), icon() and decorate(anchor). The shared shell/model use this surface; the public demo routes sources into research.html. Its small HOME/example aliases are explicit fixture metadata. A project adapter can provide another home and source helper through this same interface, without an Obsidian requirement. Heading anchors are normalized for the existing reader. Project context is preserved as an explicit bezug parameter.

Existing work and view data¶

The classic application modules read these window contracts: PRUEFANSICHT (entries, questions and work units), LAB_LANES (roles/reports/exact assignments), PROJEKTE (project workspace and strategy relationships), ERLEDIGT (work log), BERICHTE (authored reports), ZUGAENGE (explicit access points), KALENDER_GOOGLE (optional calendar snapshot), FRISCHE (explicit dated comparisons), MONITOR (findings with limits), AGENTEN (execution records or honest empty arrays). Their concrete synthetic fields are available in example-data.json and the existing model consumers. The deterministic tools/build-data.cjs builds these script assets and the reader responses from the same input. No personal filesystem is read.

GET /api/work supplies the same work entry/question shape to the reader. The demo also supplies one explicitly synthetic acceptance-review task and an empty agent-work record. Real acceptance/adoption/delivery is not implemented by this adapter. Unknown task identities and every POST are rejected, not acknowledged as successful.

UI preferences use namespaced browser storage. They are local presentation settings, not authorization or a shared account state. Demo reset clears only that namespace. A different source or synchronization backend requires its own explicit authority and error contract.

Dated configuration and coordination examples¶

GET /api/operator-sessions maps to an explicitly authored synthetic file. The positive demo-model/medium entry and all-zero example session identifiers are fiction, alongside unavailable, planned and paused cases. They demonstrate the existing metadata renderer without runtime observation. Coordination consumes the same source-bound lane and briefing contracts and the shared composer; it has no separate API or model call. Every source remains in the explicit source map, with exact original bytes and SHA256 revision.

Source-layout profiles¶

The single authored corpus supplies the generated profile registry profiles/index.json and its synchronous browser form demo-profiles.js. tools/knowledge-profiles.cjs declares project-folder, linked-notes and shared-sources. Profile source responses preserve the existing logical path, complete text and revision; storagePath identifies their actual package placement. Project, operator and result records retain those same logical references. The common renderer reads the selected profile through the static adapter.

A layout choice is presentation state in the address. Demo-only notes and preferences are separately namespaced per profile. No private application store is read or imported. Unsupported profile values use the clearly reported default. Profile selection cannot expand API or publication authority.

For a separate reader-only catalog probe, disable the authored demo registry in an independent local copy before connecting a different catalog and root source map, as the method walkthrough explains. Rebuilding the authored example restores its generated profile catalogs; it does not import a private collection.

An optional source-bound result introduction can carry a native table. Its role, assignment, result wording and project must match. The source path, SHA, complete passages, heading, caption and serialized Markdown table must match the delivered source before the table is shown. A mismatch preserves the error and original-source route rather than inventing a verified comparison.

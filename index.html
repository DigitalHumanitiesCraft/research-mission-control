Research Mission Control

0.9.0 RC2 Release candidate

Research Mission Control is a reusable method for organizing a human user, LLM-based AI agents, maintained project knowledge, implementation, and independent verification around one shared project repository. The complete system prompt initializes the method. The installable skill packages the same initialization logic with a transactional workspace scaffolder.

The three configuration questions

The initializer names Research Mission Control (public GitHub repository) and asks these questions in the human user's language. Each question includes its explanatory sentence.

  1. Which role should this working context assume within Research Mission Control: Research Orchestrator, Operational Orchestrator, or Independent Verification Agent? The working context is this separately open Codex task, Claude Code conversation, or equivalent context with its own context window. A new standard setup begins with the Research Orchestrator.
  2. What is the project, what observable result should it produce, and what criteria will the human user use to accept that result? Describe the intended result and its acceptance criteria. Derive implementation steps only after this boundary is clear.
  3. Where is the shared project workspace, and which existing data, documents, materials, code, repositories, or knowledge sources belong to the project? The project workspace is the local folder or Git worktree shared by the selected contexts. The initializer inventories material already present there and asks the human user to name only relevant inputs that cannot be discovered from the workspace.

  1. Begin with Research. Paste the complete system prompt in the first working context. The human user directs the work; the current LLM-based agent assumes the Research Orchestrator role after configuration.
  2. Confirm the configuration. Answer the three questions about role, intended result and acceptance, and the shared project workspace with its inputs.
  3. Initialize locally. After authorization, the initializer creates one new shared local Git repository. The Promptotyping core contains project.md, specification.md, journal.md, handoff.md, and INDEX.md; knowledge/integration.md carries the shared contract. communication/ contains the Context Stream protocol, index, role-owned outboxes, recipient-owned state, threads, and capsules. mission-control/roles/ contains the three complete role prompts, while the three start-*.md files bind them to the verified project.
  4. Open Operations and Verification. Open fresh second and third working contexts at the same folder. Paste start-operations.md and start-verification.md into their respective Codex tasks or Claude Code conversations.

Context Stream transport

The shared folder transports immutable messages between sessions and does not wake them. The integration contract records the tested notification route and a polling or human-mediated fallback.

External and evidence boundaries

A GitHub remote is created only after explicit authorization names its owner and visibility. Grounded Vault is requested only when substantive claims require machine-resolvable grounding and attributable human verification. It remains pending binding until a real project-specific binding is verified.

02 / Protocol

Roles and exchange

The Research Orchestrator is the human user's direct AI conversation partner. The Operational Orchestrator changes authorized project artifacts. The Independent Verification Agent works in a separate read-only context, evaluates the intended result, actual artifact, and evidence, and reports its complete finding to the human user.

SUPPORTING ROUTES

Operational Orchestrator ↔ Specialist Agents
Operational Orchestrator ── Operations Result Notice ──→ Research Orchestrator
User as Research Director ── optional finding route ──→ Research or Operations

The standard persistent route is Research → Operations → Verification → Human user. A contained profile may perform the same information functions sequentially in one context.

Persistent transport

role-owned immutable outbox
        ↓ stable thread id + canonical artifact references
recipient-owned state and sender cursor
        ↓ verified processing
single-writer canonical integration
        ↳ capsule when the thread closes or re-entry cost is material

The Context Stream Protocol is the generic file-based transport. communication/INDEX.md locates active threads and completed capsules. Promptotyping remains the durable project knowledge layer. The Direct Communication Protocol from the two-orchestrator experiment is one concrete implementation and evidence source. The method defines no universal numeric compaction threshold.

03 / Knowledge

Publication boundary

This bounded marker check does not claim general secret detection. Official skill validation remains a separate harness quality gate.
